## Context

**GDD**: `design/gdd/pet-definition-data.md`
**Requirement**: `TR-pet-definition-data-014`, `TR-pet-definition-data-005`
*(Requirement text lives in `docs/architecture/tr-registry.yaml` — read fresh at review time)*

**ADR Governing Implementation**: ADR-0002: Pet Catalog Loading, Injection and Immutability (primary); ADR-0001: Time and Event Injection (composition root)
**ADR Decision Summary**: One `CatalogManifest` `.tres` references each species `.tres` as `ext_resource` (never path strings); `PetCatalogLoader.load_catalog()` loads it and calls `build_catalog()`; `GameRoot` does this synchronously in `_ready()` before constructing any logic object.

**Engine**: Godot 4.7.1 | **Risk**: HIGH
**Engine Notes**: The manifest's `species` is an `@export var species: Array[SpeciesDefinition]` filled in the inspector — stored as `ext_resource` refs so export dependency tracking includes every species. **godot#98798** (typed `Array[CustomResource]` loading empty in exported builds) is not confirmed fixed in 4.7.1 — this story only proves the editor/headless path; Story 009 proves the exported one.

**Control Manifest Rules (this layer)**:
- Required: only `PetCatalogLoader` loads anything under `res://assets/data/pets/`
- Forbidden: `pet_data_load_outside_loader`; `autoload_access_from_logic`; `sprite_frames_mutation` (placeholder generation writes files from a tool script, never mutates at runtime)
- Guardrail: catalog load completes before the first frame; one-time boot cost outside the 16.6 ms budget

## Implementation Notes

*Derived from ADR-0002 §3–5:*

- Files: `src/core/pet_data/catalog_manifest.gd` (`class_name CatalogManifest extends Resource`, `@export var species: Array[SpeciesDefinition]`), `load_catalog` added to `pet_catalog_loader.gd`, `assets/data/pets/catalog_manifest.tres`, `assets/data/pets/bloop/bloop.tres`, `assets/data/pets/bloop/sprites/*.tres` + atlas PNGs.
- One species per file: forms, profiles and the rule table are embedded sub-resources in `bloop.tres`; sprite sets may be external `.tres`.
- **Placeholder art**: a tool script under `tools/asset-pipeline/` (e.g. `make_placeholder_sprites.gd`, run via `godot --headless --script`) draws simple 32×32 frames in bloop's palette and writes the `SpriteFrames` `.tres` files. Label each frame with its animation initial so they're distinguishable on the LCD. Real art replaces these later without schema changes.
- `load_catalog` on a missing or wrong-typed manifest returns a `FAILED` catalog with an error, never crashes.
- `GameRoot` holds the catalog; per-pet consumers receive profiles, not the catalog (ADR-0002 §5) — that wiring lands with the Need System epic.
- The shipped-catalog fixture does real file I/O, so it lives in `tests/integration/`, not `tests/unit/` (ADR-0002 §5, PDD OQ#13). The GDD AC still says `tests/unit/` — note the ADR override in the test's header comment.

## QA Test Cases

*Written at story creation (solo mode — qa-lead not consulted). The developer implements against these — do not invent new test cases during implementation.*

- **AC-1**: shipped catalog loads
  - Given: `res://assets/data/pets/catalog_manifest.tres`
  - When: `load_catalog(path, true)`
  - Then: `state == READY`; `get_all_species().size() >= 1`; `get_hatchable_species().size() >= 1`
- **AC-2**: bloop values
  - Given: the loaded catalog
  - Then: every value in the bloop AC above matches exactly (stages, needs, care, rule table, form ids)
- **AC-3**: shipping gate
  - Given: the loaded catalog
  - Then: no species has a rule whose `min_share` sum exceeds 1.0; hatchable list non-empty; `arc_band_warning` empty for bloop (arc 9)
  - Edge cases: a fixture manifest with an unreachable-rule species makes the gate assertion fail (proves the gate gates)
- **AC-4**: new species without code change
  - Given: `tests/fixtures/pet_data/two_species_manifest.tres` referencing bloop plus a fixture species
  - When: `load_catalog`
  - Then: both resolve by id
- **AC-5**: bad manifest path
  - Given: a non-existent path
  - Then: `state == FAILED`, an error logged, no crash
- **AC-6**: boot load
  - Given: `GameRoot.tscn` instantiated in the tree
  - When: `_ready()` completes
  - Then: `GameRoot`'s catalog is `READY` on the first frame, and no logic object was constructed before it (assert order via the construction sequence)
- **AC-7**: placeholder sprites are regenerable
  - Given: the tool script
  - When: run headless
  - Then: the regenerated `.tres` files are byte-identical to the committed ones (deterministic output)
